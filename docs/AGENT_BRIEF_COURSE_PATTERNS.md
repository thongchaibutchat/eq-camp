# บรีฟสอนเอเจน — แพตเทิร์นหลักสูตร EQ Camp ที่ "ห้ามผิด ห้ามพลาด"

> ถอดจากโค้ดจริง (`src/eqcamp-core.ts` : `compose()`, `buildSchedule()`, และข้อมูล `COURSES`/`REF_ACTIVITIES` ใน `src/eqcamp-data.ts`)
> อ่านไฟล์นี้ก่อนแก้ตรรกะเอกสารทุกครั้ง — เป็นสัญญาว่าเอกสารโปรแกรมค่าย (PL) จะหน้าตาเหมือนกันทุกครั้ง ไม่ว่าใคร/เอเจนไหนสร้าง

---

## 0. ภาพรวม 1 บรรทัด
หลักสูตร 1 ตัว = **รหัส PL จริง + ชื่อไทย/อังกฤษ + วัตถุประสงค์จริง 2 ข้อ (obj1,obj2) + family + คลังกิจกรรมแยก kind** → ป้อนเข้า "แม่แบบตายตัว" ที่เหลือระบบเติมเอง **ตัวแปรเปลี่ยนได้ตามบรีฟ แต่โครงห้ามเปลี่ยน**

---

## 1. โครงเอกสาร "ตายตัว" ที่โผล่ทุกครั้ง (compose) — ผิดลำดับ/ผิดจำนวน = ผิด

### 1.1 วัตถุประสงค์การเรียนรู้ = **4 ข้อเป๊ะเสมอ**
1. `obj1` ของหลักสูตรจริง (ถ้าไม่ผูกหลักสูตร → ข้อความ fallback ของ family)
2. `obj2` ของหลักสูตรจริง (หรือ fallback)
3. **คงที่ตายตัว** : "เพื่อจัดกระบวนการเรียนรู้ให้ผู้เรียนได้เกิดเจตคติที่ดีต่อการเรียน…ใฝ่ฝึกฝนตนเองอยู่เสมอ…"
4. **คงที่ตายตัว** : "เพื่อจัดกระบวนการเรียนรู้…สร้างสรรค์อย่างมีความสุข…สร้างองค์ความรู้ใหม่ได้ในศตวรรษที่ 21"
> **ห้ามผิด:** ข้อ 3-4 ห้ามแก้/สลับ/ตัดเด็ดขาด. ข้อ 1-2 ต้องมาจาก `COURSES[code].obj1/obj2` — **ห้ามแต่งเอง** ถ้าผูกหลักสูตรไว้

### 1.2 กิจกรรมเชิงบูรณาการ (acts)
- ยึด **กิจกรรมของหลักสูตรที่เลือก** เป็นหลักเสมอ (ไม่ใช่กิจกรรมกลาง ๆ)
- เรียงลำดับ kind : **core → night → opening → recreation → closing** (ค่าคงที่ `ORD`)
- รวมชื่อฐาน (ตัด `EP.1/EP.2/Part/ (ต่อยอด)` ออก) ไม่ให้ซ้ำ → **สูงสุด 6 ข้อ**
- **ปิดท้ายด้วย "กิจกรรมทดสอบหลังการเรียนรู้ (After Action Review : AAR)" เสมอ** (ข้อสุดท้าย)
> **ห้ามพลาด:** AAR ต้องเป็นข้อสุดท้ายเสมอ, ต้องพอดีหน้าแรก 1 หน้า (เกิน 6 ข้อ = ล้น)

### 1.3 บูรณาการการเรียน (integ) = 5–7 ข้อ, **หัว-ท้ายตายตัว**
- ข้อ 1-2 คงที่ : "บูรณาการคุณลักษณะ…ศตวรรษที่ 21" / "บูรณาการโดยใช้โครงการ…ภารกิจระหว่างกิจกรรม"
- ตรงกลาง = `S.extra` ของ family (หรือกรณี steam ผูกหลักสูตรย่อย = บูรณาการสหวิทยาการ/ทักษะวิชาชีพด้าน<หัวข้อ>)
- **3 ข้อท้ายคงที่เสมอ** : Collaborative and Leadership Skills / Learning and Innovation Skills / Communication Tactic
- ตัดไม่เกิน 7 ข้อ (พอดีหน้าแรก)

### 1.4 ชื่อหลักสูตร ไทย/อังกฤษ
- ชื่อในคลังรูป `"ชื่อไทย (English Name)"` → **ไทยบรรทัดบน + "( English )" บรรทัดล่าง** เสมอ
- `nameTh` (ไม่มีวงเล็บอังกฤษ ไม่มีคำว่า "หลักสูตร") ใช้ในหน้ากำหนดการ

### 1.5 จำนวน / งบประมาณ / ระยะเวลา
- สูตรทีมงาน (`staffText`) ตายตัว : 25-50→4-5 · 50-120→6-8 · 120-180→8-12 · 180-300→10-16
- งบประมาณประกอบอัตโนมัติจาก (ที่พักถ้ามีคืน · อาหารหลัก/ว่างตามจำนวนมื้อจริง · ห้องประชุม · วิทยากร · เดินทาง · ทัศนศึกษาถ้ามี · อุปกรณ์)
- ระยะเวลา : half→"ครึ่งวัน (ไป-กลับ)" · day→"N วัน (ไป-กลับ)" · overnight→"N วัน M คืน"

## 2. แพตเทิร์นกำหนดการ "ตายตัว" (buildSchedule) — โผล่ทุกครั้ง

### 2.1 durationMode มี 3 แบบ และกฎเหล็ก
| mode | นิยาม | ห้ามมี |
|---|---|---|
| `half` | ครึ่งวัน ไป-กลับ | เช็คอิน/อาหารเย็น/อาหารเช้า/พักผ่อนฝันดี/กิจกรรมกลางคืน |
| `day` | เต็มวัน ไป-กลับ (จัดที่โรงเรียนได้) | เช็คอิน/อาหารเย็น/พักค้าง |
| `overnight` | พักค้าง (**nights>0 เท่านั้น**) | — (มีได้หมด) |
> **ห้ามพลาด:** overnight เท่านั้นที่ `nights>0`. half/day ถ้ามีคำพักค้างหลุดเข้ามา = บั๊ก (มี `check()` ดักไว้)

### 2.2 Day Camp (mode=day) แพตเทิร์น 08.30–16.00 ตายตัว
ลงทะเบียน/พิธีเปิด(วันแรก) → opening 1 ชม. → ปูพื้นฐาน 20 นาที → ว่าง → **core EP.1 (85') → กลางวัน → core EP.2 (120')** → ว่าง → สรุป/ AAR(วันสุดท้าย)
- แพตเทิร์น STEAM (5 STEPs + EDP + "STEAM Mission") ใช้กับ **PL STM 0101 เท่านั้น** — หลักสูตรอื่นใช้ชื่อกิจกรรมของหลักสูตรนั้นเป็นหัวข้อช่วงตรง ๆ

### 2.3 Overnight วันแรก : เลือกโครงตาม "เวลาถึงสถานที่" (กันช่วงว่าง)
- คำนวณ `arr = เวลาออก + เวลาเดินทาง + 30 นาที` → เลือก 1 ใน 4 เทมเพลต (ถึงก่อน 09.30 / 09.30–11.00 / 11.00–12.30 / บ่าย)
- **ไม่มี `venueVisit` → ช่อง `trip` กลายเป็น `core`** (เติมกิจกรรมหลักสูตร ไม่ปล่อยว่าง)
- วันกลาง = วนกิจกรรม+มื้อ+ภาคค่ำ+พักผ่อน · วันสุดท้าย = อาหารเช้า→เช็คเอาท์→นันทนาการ→ปิดค่าย→AAR→มอบรางวัล→กลางวัน→กลับ

### 2.4 กฎการเติมกิจกรรม (ทุก mode)
- **ทุกช่อง core ต้องมีกิจกรรมจริง ห้ามเว้นว่าง**
- ดึงจากคลังของหลักสูตร (kind=core) ตามลำดับ; ถ้าใช้หมดคลัง → **วนซ้ำแล้วติดป้าย "(ต่อยอด)"**
- ผู้ใช้กำหนดรายช่อง (`coreSlotIds[slotIdx]`) ได้ → ใช้ตัวที่เลือกก่อน
- `opening/night/recreation/closing` ใช้ `pick1(kind)` : **หยิบกิจกรรมของหลักสูตรที่ kind นั้นก่อน** แล้วค่อย fallback
  - เช่น ดาราศาสตร์ → ภาคค่ำ = ส่องกล้องดูดาว / ทะเล → ภาคค่ำ = ปาร์ตี้ธีม Under The Sea (มาจากคลังหลักสูตรเอง)
- มื้ออาหารนับเลขต่อเนื่อง (`mealNo`) · อาหารว่างนับแยก (`meals.s`)

### 2.5 หน้ากำหนดการต้องมี 5 อย่าง (ฟิลด์ว่างไม่ขึ้น)
`กำหนดการ` → ชื่อหลักสูตรไทย+อังกฤษ → โรงเรียน → วันที่(ถ้ามี) → สถานที่(ถ้ามี) → ปิดท้ายด้วย **"หมายเหตุ : กำหนดการอาจจะเปลี่ยนแปลงตามความเหมาะสม"** เสมอ

## 3. กฎ "ห้ามผิดเด็ดขาด" (critical invariants) — เช็คทุกครั้งก่อนออกไฟล์

1. **รหัส PL จริงเท่านั้น** (14 รหัสในทะเบียน) → `docCode = "<code>/2569"` — **ห้ามเดา/มั่ว**
2. **obj1/obj2 ต้องมาจากหลักสูตรจริง** · วัตถุประสงค์ข้อ 3-4 และ integ หัว 2 + ท้าย 3 **คงที่**
3. **durationMode** : overnight เท่านั้นที่พักค้าง; half/day ห้ามมีรายการพักค้าง
4. **กำหนดการห้ามเว้นว่าง** ทุกช่อง; เกินคลัง → วน "(ต่อยอด)"
5. **เอกสารภายใน (runsheet) + ต้นทุน/กำไร ห้ามหลุดฉบับลูกค้า** · หนังสือโรงแรมห้ามโชว์ราคาขาย/ต้นทุน
6. **ห้าม `Number(null)`** — ค่าที่อ่านไม่ได้ = "missing" + เตือน ไม่เดา (กัน "NaN.NaN" ในเวลา)
7. **ภาพต้องมีสิทธิ์** (ของทีม/สื่อทางการโรงแรม) — **ห้ามดึงภาพจากเว็บ / ห้ามปลอมภาพให้ครบ 6-8** (ถ้าไม่ถึงให้เตือนทีมเติม)
8. **ถ้อยคำ/ภาพ STEAM** ใช้เฉพาะ PL STM 0101 — ค่ายวิทย์อื่น (ดาราศาสตร์/ทะเล/ธรณี/นิติวิทย์) ห้ามมีคำว่า STEAM
9. ฟอนต์ TH Sarabun New ฝังในไฟล์เสมอ · หัวกระดาษ+เลขหน้าทุกหน้า · ราคา+งบขึ้นหน้าใหม่
