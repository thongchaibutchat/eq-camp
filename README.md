# EQ Camp — ระบบสร้างเอกสารกระบวนการขายค่ายวิชาการ

สร้างเอกสารขายค่ายวิชาการเป็นไฟล์ **Word (.docx)** จากบรีฟภายใน ~30 นาที
รองรับ 4 เอกสารในกระบวนการขายเดียว (ดึงข้อมูลชุดเดียวกัน จึงตรงกันทั้งกระบวนการ):

1. **โปรแกรมค่าย (PL xxxx/2569)** — วัตถุประสงค์ + กิจกรรมบูรณาการ + กำหนดการ + ราคา + ภาพ
2. **ใบเสนอราคา (QT)** — ตารางรายการ ราคา/ท่าน ยอดรวม เงื่อนไข ลายเซ็น
3. **หนังสือขอราคา/จองโรงแรม (BK)** — สำหรับซัพพลายเออร์ (ไม่โชว์ราคาขาย/ต้นทุน)
4. **Run-down ทีมงาน + ต้นทุน (RD)** — ภายใน: กำหนดการ + ช่องผู้รับผิดชอบ + กำไร/Margin

## เปิดใช้งานทันที
ดับเบิลคลิก `EQ_Camp_Generator.html` (เปิดในเบราว์เซอร์ ไม่ต้องติดตั้ง ไม่ต้องต่อเซิร์ฟเวอร์)
> ไฟล์นี้สร้างจาก `npm run build` — ถ้ายังไม่มี ให้รัน build ก่อน

## พัฒนา / สร้างใหม่
```bash
npm install
npm run build      # → EQ_Camp_Generator.html (standalone)
npm run validate   # ตรวจไฟล์ samples/*.export.json ตาม schema.json
```

## โครงสร้าง
```
src/eqcamp-core.ts   แกนกลาง: parser บรีฟ, เครื่องจัดกำหนดการ, ตัวร้อยประโยค, ตัวตรวจ, ตัวสร้าง 4 เอกสาร (docx)
web/                 UI (React) — App.tsx + entry/index/shim
schema.json          สัญญาข้อมูลกลาง (ไฟล์ export JSON) — JSON Schema draft 2020-12
samples/             ไฟล์ .docx ตัวอย่าง + sample.export.json
docs/                วิเคราะห์ "เหมือน/ต่าง" ของแต่ละโปรแกรม
AI_HANDOFF.md        คู่มือทำงานร่วมกันระหว่างเอเจนต์ AI (อ่านก่อนเริ่ม)
```

## ทำงานร่วมกันหลายเอเจนต์ (Claude + ChatGPT/Codex)
อ่าน **AI_HANDOFF.md** ก่อนเสมอ หลักสำคัญ:
- repo นี้ = แหล่งความจริงเดียว ทำงานผ่าน branch → commit → PR
- `src/eqcamp-core.ts` เป็นแกนกลาง **แก้ที่เดียว** ทุกส่วนต่อยอดด้วยการ import ไม่ก๊อปตรรกะ
- ข้อมูลงานจริงแลกกันผ่านไฟล์ `*.export.json` ตาม `schema.json`
- เปลี่ยนโครงข้อมูลเมื่อไร ต้องเพิ่ม `_v` และอัปเดต `schema.json` พร้อมกัน

## กติกาซิงก์ (กันทำงานทับกัน)
1. ก่อนเริ่มงานทุกครั้ง: `git pull` ให้ได้ล่าสุด
2. แตก branch ของตัวเอง (เช่น `feature/chatgpt-sheets-import`, `feature/claude-core-*`)
3. commit พร้อมข้อความสั้นชัด แล้วเปิด PR ให้รีวิวก่อน merge เข้า `main`
4. ใครแก้ `src/eqcamp-core.ts` หรือ `schema.json` ต้องระบุใน PR ให้อีกฝ่ายทราบ
